**Idea clave.** La **[UART](../glosario/#uart)** (*Universal Asynchronous Receiver-Transmitter*) manda bytes de uno en uno por un solo hilo (TxD) y los recibe por otro (RxD), sin reloj compartido. Por eso los dos extremos tienen que acordar de antemano el **formato** y la **velocidad**. El LPC1768 tiene cuatro (UART0–UART3). En la Mini-DK2, la **UART0** (P0.2 y P0.3) va a un conversor USB-serie: es la que se usa para hablar con el PC y la que usa el *bootloader* para grabar la flash.

## La trama

En reposo la línea está a **1**. Cada byte va así:

- **Start**: un bit a 0. Su flanco de bajada avisa al receptor de que empieza un byte.
- **Datos**: 8 bits (pueden ser 5–8), **primero el de menos peso**.
- **[Paridad](../glosario/#paridad)** (opcional): un bit que hace par (o impar) el número de unos, para detectar un bit erróneo.
- **Stop**: 1 o 2 bits a 1. Devuelve la línea a reposo y deja ver el flanco del siguiente start.

El formato más usado es **8N1** (8 datos, sin paridad, 1 stop): 10 bits por byte. Cada bit dura $t_{bit} = 1/V$, y la velocidad $V$ se da en bit/s o [baudios](../glosario/#baudio) (en la UART cada símbolo es un bit, así que es lo mismo): 9600, 19 200, 115 200… A 115 200 bit/s, un bit dura 8,7 µs y un byte 8N1, 87 µs.

Para enlazar dos equipos, el **TxD de uno va al RxD del otro** (cruzados) y las masas unidas. Así se conectan un GPS, un módulo GSM o Bluetooth, un LiDAR…

## La configuración

1. **Pines** con PINSEL: P0.2 → TXD0 y P0.3 → RXD0 (función 01).
2. **Alimentación** con PCONP (UART0 y UART1 ya están encendidas tras el reset; UART2 y UART3 no).
3. **Formato** en [LCR](../glosario/#lcr) (*Line Control Register*).
4. **Velocidad** con [DLL y DLM](../glosario/#dl) (*Divisor Latch*, byte bajo y alto del divisor) y [FDR](../glosario/#fdr) (*Fractional Divider Register*). Para poder escribirlos hay que poner a 1 el bit [DLAB](../glosario/#dlab) (*Divisor Latch Access Bit*) de LCR: DLL y DLM comparten dirección con los registros de datos, y DLAB elige cuál se ve.
5. **Interrupciones** en [IER](../glosario/#ier) (*Interrupt Enable Register*) y en el NVIC.

## La velocidad

El reloj de la UART se divide entre 16 (cada bit se muestrea 16 veces) y entre el divisor $DL = 256\cdot DLM + DLL$ (16 bits). El **divisor fraccionario** (FDR) afina aún más:

$$
V = \frac{F_{PCLK}}{16\cdot(256\cdot DLM + DLL)\cdot\left(1 + \frac{DivAddVal}{MulVal}\right)}
$$

<Donde>

- $V$: velocidad de la línea, en bit/s.
- $F_{PCLK}$: reloj de la UART, en Hz (25 MHz por defecto).
- $16$: muestras por bit. El receptor mira la línea 16 veces en cada bit para encontrar su centro.
- $DLM$, $DLL$: byte alto y bajo del divisor, de 0 a 255 cada uno. Juntos, $DL = 256\cdot DLM + DLL$.
- $DivAddVal$, $MulVal$: los dos campos de FDR (de 0 a 14 y de 1 a 15). El paréntesis vale entre 1 y casi 2.

</Donde>

En la mayoría de los casos basta con DL (tras el reset, DivAddVal = 0 y el factor vale 1):

$$
DL = \frac{F_{PCLK}}{16\cdot V} \ \text{redondeado}
\qquad
DLM = DL / 256 \qquad DLL = DL \,\%\, 256
$$

<Donde>

- $DL / 256$: división entera (el cociente). $DL \,\%\, 256$: el resto. Así se parte DL en sus dos bytes.

</Donde>

Como DL tiene que ser entero, la velocidad real no es justo la pedida. El error relativo es:

$$
\varepsilon = \frac{V_{real} - V}{V}\cdot 100\ \%
\qquad
V_{real} = \frac{F_{PCLK}}{16\cdot DL}
$$

<Donde>

- $V$: la velocidad pedida y $V_{real}$ la que sale con el DL redondeado, en bit/s.
- $\varepsilon$: error en %. Positivo si la UART va más rápida de lo pedido.

</Donde>

Por ejemplo, con $F_{PCLK} = 25$ MHz y 19 200 bit/s: $DL = 81{,}38 \to 81$ y la velocidad real es 19 290 bit/s (0,47 % de error, sin problema). Con 115 200 bit/s el redondeo da $DL = 14$ y un error del 3,1 %, ya demasiado; ahí entra el fraccionario.

**Qué hace el divisor fraccionario.** Multiplica DL por $1 + DivAddVal/MulVal$, así que el divisor total **ya no tiene que ser entero**. Por ejemplo, para 115 200 bit/s hace falta un divisor total de $25\cdot 10^6/(16\cdot 115\,200) = 13{,}56$. Con $DL = 9$, $DivAddVal = 1$ y $MulVal = 2$ el divisor es $9\cdot 1{,}5 = 13{,}5$: salen 115 741 bit/s, un 0,47 % de error.

## Transmitir y recibir

Hay dos registros de datos de 8 bits en la misma dirección: **[THR](../glosario/#thr)** (*Transmit Holding Register*: lo que se escribe se envía) y **[RBR](../glosario/#rbr)** (*Receiver Buffer Register*: lo que se lee es lo recibido).

- **Tx**: empieza al **escribir en THR**. El byte pasa al **[registro de desplazamiento](../glosario/#tsr)**, que lo saca bit a bit por TxD. En ese momento THR queda vacío y salta la interrupción **[THRE](../glosario/#thre)** (*THR Empty*): ya cabe el siguiente, aunque el anterior aún esté saliendo.
- **Rx**: el flanco de bajada del start arranca la recepción, se muestrean los bits y, con el stop, el byte queda en **RBR** y salta la interrupción **RDA** (*Receive Data Available*).

`(IIR >> 1) & 0x07` desplaza IIR un bit a la derecha (para quitar IntStatus) y se queda con los tres bits de IntId: sale un número del 0 al 7 que dice qué ha pasado.

**La FIFO y LSR.** Las UART del LPC1768 tienen una **[FIFO](../glosario/#fifo)** (*First In, First Out*, una cola) de 16 bytes para recibir y otra para transmitir. Con ella, la UART puede guardar varios bytes antes de que la CPU los lea. El *time-out* de la FIFO salta cuando quedan bytes en la cola de recepción y lleva un rato sin llegar ninguno, para que no se queden olvidados. El registro **[LSR](../glosario/#lsr)** (*Line Status Register*) dice el estado de la línea: si hay un dato recibido, si THR está vacío y si ha habido errores de paridad, de trama o de desbordamiento.
```c
void uart0_init(void) {
  LPC_PINCON->PINSEL0 |= (1 << 4) | (1 << 6);  // P0.2 = TXD0, P0.3 = RXD0
  LPC_UART0->LCR = (1 << 7) | 0x03;            // DLAB = 1; 8 bits, sin paridad, 1 stop
  LPC_UART0->DLL = 81;                         // 19 200 bit/s con F_PCLK = 25 MHz
  LPC_UART0->DLM = 0;
  LPC_UART0->LCR = 0x03;                       // DLAB = 0
  LPC_UART0->IER = (1 << 0) | (1 << 1);        // RDA y THRE
  NVIC_EnableIRQ(UART0_IRQn);
}
```

### Mandar una cadena con interrupciones

El primer carácter se escribe fuera de la ISR; cada interrupción THRE manda el siguiente, hasta el `'\0'`. Mientras tanto, el programa principal sigue con lo suyo.

```c
char *ptr_tx;                 // siguiente carácter que hay que mandar
char tx_completa;
char buffer[32];              // línea recibida (RDA); 32 es un tamaño de ejemplo
char *ptr_rx = buffer;        // dónde se guarda el siguiente byte recibido
volatile char rx_completa;    // la ISR lo pone a 1 cuando llega '\r'

void tx_cadena_UART0(char *cadena) {
  ptr_tx = cadena;
  tx_completa = 0;
  LPC_UART0->THR = *ptr_tx++;              // el primero, a mano
}

void UART0_IRQHandler(void) {
  switch ((LPC_UART0->IIR >> 1) & 0x07) {  // leer IIR borra la THRE
    case 2:                                // RDA: ha llegado un byte
      *ptr_rx = LPC_UART0->RBR;            // leer RBR borra la RDA
      if (*ptr_rx == '\r') {               // fin de línea: cadena completa
        *ptr_rx = '\0';
        rx_completa = 1;
        ptr_rx = buffer;
      } else {
        ptr_rx++;
      }
      break;
    case 1:                                // THRE: cabe el siguiente
      if (*ptr_tx) LPC_UART0->THR = *ptr_tx++;
      else tx_completa = 1;
      break;
  }
}
```

La cadena tiene que seguir existiendo hasta que acabe de enviarse (una variable global, no un *array* local de una función que ya ha terminado). Y en la recepción conviene comprobar que `ptr_rx` no se sale de `buffer`.

<details>
<summary>¿Por qué se manda el primer carácter fuera de la ISR?</summary>

Porque la interrupción THRE salta cuando THR **pasa a estar vacío**. La interrupción THRE solo se produce después de que THR haya recibido algún dato y lo haya pasado al registro de desplazamiento: mientras no se escriba en THR, no hay nada que se vacíe y no salta ninguna. Por eso hay que escribir el primer carácter a mano. Una vez hecho, cada THRE posterior encadena el siguiente. *(Respuesta redactada a partir de los apuntes.)*

</details>

<details>
<summary>¿Qué error máximo de velocidad aguanta una UART con 8N1?</summary>

El receptor se sincroniza en el flanco del start y muestrea cada bit hacia su centro. Hasta el bit de stop pasan unos 9,5 bits, y el error acumulado no puede llegar a medio bit: en total, menos de un 5 % entre los dos extremos (en la práctica se busca menos del 2 %). *(Respuesta redactada: es la regla general de cualquier UART.)*

</details>
