**En el examen vale el pseudocódigo.** El profesor acepta pseudocódigo claro en las preguntas de código: no hace falta el C completo. Lo que no puede faltar son los **valores de los registros** (MR0, MCR, PCR, CCR…) y lo que hace cada estado. Por eso cada solución empieza con una **respuesta corta en pseudocódigo**; el C completo sigue debajo. Los pasos de cada tipo de problema están en el [modo examen](../examen/).

**Cómo usar este tema.** Son problemas **nuevos**, escritos con el mismo estilo que los de examen: un sistema con entradas y salidas, una máquina de estados o un StateChart y su código para el LPC1768. Lee el enunciado, intenta el diagrama y el código en papel y luego abre la solución.

## El método

1. **Entradas, salidas y eventos.** ¿Qué llega (pulsadores, sensores, bytes, *timeouts*)? ¿Qué hay que mover?
2. **Estados.** Un estado es **lo que hay que recordar** para decidir. Si dos situaciones reaccionan igual a todo, son el mismo estado.
3. **Transiciones.** Para cada estado y cada evento: ¿a dónde va?, ¿con qué condición?, ¿qué acción? Lo que sea común a muchos estados, a un **superestado**.
4. **Dónde corre la máquina.** En la ISR del periférico que trae los eventos (UART, captura) o en una ISR periódica (SysTick, Timer) si hay tiempos.
5. **Código.** Un `switch (estado)`, cada caso da un paso y vuelve.

## Problema 1. Tramas por la UART

<details>
<summary>Enunciado</summary>

Un sensor manda por la UART0 tramas con este formato:

| Byte | Contenido |
|---|---|
| 1 | Cabecera, siempre 0x7E |
| 2 | Longitud L, de 1 a 16 |
| 3 … L + 2 | L bytes de datos |
| L + 3 | Checksum: suma de L y de los datos, módulo 256 |

a) Dibuja la máquina de estados que reconoce las tramas byte a byte.
b) Prográmala en la ISR de la UART0. Una trama correcta se deja en `trama[]` y se avisa con `trama_ok = 1`.
c) ¿Qué pasa si se pierde un byte? Propón una solución.

</details>

<details>
<summary>Solución guiada</summary>

**Respuesta corta (pseudocódigo).**

```text
Configuración (UART0, 8N1, interrupción al recibir):
  PINSEL0: P0.2 = TXD0, P0.3 = RXD0
  LCR = 0x83 · DLL, DLM = divisor de la velocidad · LCR = 0x03
  IER = 1 (RDA) · habilitar UART0_IRQn en el NVIC

ISR de la UART0 (cada byte, un paso):
  si IntId no es RDA: salir
  b = RBR · ms_sin_bytes = 0
  según estado:
    ESPERA_CAB: si b == 0x7E → LONGITUD
    LONGITUD:   si 1 ≤ b ≤ 16 → len = b, suma = b, i = 0, DATOS
                si no → ESPERA_CAB
    DATOS:      trama[i++] = b · suma += b · si i == len → CHECKSUM
    CHECKSUM:   si b == suma (módulo 256) → trama_ok = 1
                → ESPERA_CAB

ISR periódica de 1 ms (apartado c):
  ms_sin_bytes++ · si pasa de 2 y estado ≠ ESPERA_CAB → ESPERA_CAB
```

**Paso a paso, con el C completo:**

**a)** Hay que recordar en qué parte de la trama vamos: cuatro estados.

- **ESPERA_CAB**: llega 0x7E → LONGITUD. Cualquier otro byte se ignora.
- **LONGITUD**: llega L. Si `[1 ≤ L ≤ 16]` → DATOS, con la acción `suma = L, i = 0`. Si no → ESPERA_CAB (trama imposible).
- **DATOS**: cada byte `/ trama[i++] = b, suma += b`. Cuando `[i == L]` → CHECKSUM.
- **CHECKSUM**: si `[b == suma]` → ESPERA_CAB `/ trama_ok = 1`; si no, → ESPERA_CAB sin más.

Es una máquina **Mealy**: las acciones van en las transiciones.

**b)** La máquina corre en la ISR de recepción (RDA): **cada interrupción trae un byte y da un paso**. No hay ningún bucle esperando el siguiente.

```c
typedef enum { ESPERA_CAB, LONGITUD, DATOS, CHECKSUM } estado_rx_t;
static estado_rx_t estado_rx = ESPERA_CAB;
static uint8_t trama[16], len, i, suma;   // uint8_t: la suma ya es módulo 256
volatile uint8_t trama_ok;
volatile uint32_t ms_sin_bytes;                    // ms desde el último byte; lo incrementa la ISR periódica (apartado c)

void UART0_IRQHandler(void) {
  uint8_t b;
  if (((LPC_UART0->IIR >> 1) & 0x07) != 2) return;   // solo RDA
  b = LPC_UART0->RBR;                                // leer borra la interrupción
  ms_sin_bytes = 0;                                  // para el timeout del apartado c
  switch (estado_rx) {
    case ESPERA_CAB:
      if (b == 0x7E) estado_rx = LONGITUD;
      break;
    case LONGITUD:
      if (b >= 1 && b <= 16) { len = b; suma = b; i = 0; estado_rx = DATOS; }
      else estado_rx = ESPERA_CAB;
      break;
    case DATOS:
      trama[i++] = b;
      suma += b;
      if (i == len) estado_rx = CHECKSUM;
      break;
    case CHECKSUM:
      if (b == suma) trama_ok = 1;                   // el programa principal la procesa
      estado_rx = ESPERA_CAB;
      break;
  }
}
```

**c)** La máquina solo avanza cuando llegan bytes. Si se pierde uno, se queda en DATOS y toma la cabecera de la trama siguiente como dato: se pierden dos tramas. Solución: un **timeout**. Una ISR periódica (por ejemplo, de 1 ms) incrementa `ms_sin_bytes`, y si pasa de unos pocos tiempos de byte (a 115 200 bit/s, un byte son 87 µs; 2 ms es de sobra) con la máquina fuera de ESPERA_CAB, la devuelve a ESPERA_CAB.

Otro detalle: si llega otra trama mientras el programa principal está leyendo `trama[]`, se pisa. Se puede copiar la trama a otro buffer al validarla o no aceptar otra hasta que `trama_ok` vuelva a 0.

</details>

## Problema 2. Barrera de aparcamiento con un servo

<details>
<summary>Enunciado</summary>

Una barrera la mueve un servo en PWM1.1 (0° cerrada, 90° abierta; pulso nominal de 1 ms a 0° y 2 ms a 180°, periodo de 20 ms; F_PCLK = 25 MHz). Hay:

- un pulsador **TICKET** que pide abrir;
- un sensor **S** que vale 1 mientras hay un coche bajo la barrera;
- un pulsador de **EMERGENCIA** que la abre del todo y la deja abierta hasta pulsar **REARME**.

La barrera debe moverse **despacio** (1° cada 20 ms), quedarse abierta **5 s** cuando no haya coche, y si aparece un coche **mientras baja**, volver a subir.

a) Dibuja el StateChart.
b) Calcula PWM1MR0 y el valor de MR1 para un ángulo.
c) Programa la máquina, llamada cada 20 ms.

</details>

<details>
<summary>Solución guiada</summary>

**Respuesta corta (pseudocódigo).**

```text
PWM1 para el servo (PWM1.1, F_PCLK = 25 MHz, PR = 0):
  PINSEL: pin a PWM1.1
  PWM1MR0 = 499 999 (20 ms) · MCR = PWMMR0R
  PCR = PWMENA1 · LER = bits 0 y 1 · TCR = Counter Enable + PWM Enable
  servo(g): MR1 = 25 000 + 25 000·g/180 · LER = bit 1

Tick de 20 ms (un Timer con MR0 = 499 999, MR0I | MR0R):
  si EMERGENCIA y estado ≠ EMERGENCIA: ángulo = 90, servo → EMERGENCIA
  según estado:
    CERRADA:    si TICKET → ABRIENDO
    ABRIENDO:   si ángulo < 90: ángulo++, servo
                si ángulo ≥ 90: t = 0 → ABIERTA
    ABIERTA:    t++ · si t ≥ 250 y no hay coche → CERRANDO
    CERRANDO:   si hay coche → ABRIENDO
                si no: ángulo--, servo · si ángulo == 0 → CERRADA
    EMERGENCIA: si REARME → CERRANDO
  (estado inicial: CERRANDO)
```

**Paso a paso, con el C completo:**

**a)** Estados dentro de un superestado **FUNCIONANDO**:

- **CERRADA**: TICKET → ABRIENDO.
- **ABRIENDO**: do: `ángulo++` cada tick. `[ángulo ≥ 90]` → ABIERTA (con ≥ y no ==, por si se entra ya arriba, como tras el reset con un coche debajo).
- **ABIERTA**: entry: `t = 0`. do: `t++`. `[t ≥ 250 && S == 0]` → CERRANDO (250 ticks de 20 ms son 5 s).
- **CERRANDO**: do: `ángulo--`. `S == 1` → ABRIENDO (seguridad). `[ángulo == 0]` → CERRADA.

Y fuera:

- **FUNCIONANDO** —EMERGENCIA→ **EMERGENCIA** (entry: `ángulo = 90`). Una sola flecha desde el superestado vale para sus cuatro subestados: es la ventaja de la jerarquía.
- **EMERGENCIA** —REARME→ **FUNCIONANDO**. El estado inicial de FUNCIONANDO es **CERRANDO**, no CERRADA: así, tras el reset o el rearme, la barrera baja despacio (y si hay un coche, vuelve a subir).

**b)** $PWM1MR0 = 25\cdot 10^6/50 - 1 = 499\,999$. El ancho va de 1 ms (25 000 cuentas) a 2 ms (50 000) en 180°:

$$
MR1 = 25\,000 + 25\,000\cdot\frac{grados}{180}
\qquad
90^\circ \to 37\,500
$$

```c
void set_servo(int grados) {
  LPC_PWM1->MR1 = 25000 + 25000 * grados / 180;
  LPC_PWM1->LER = (1 << 1);                // se aplica en el siguiente periodo
}
```

**c)** Los eventos de los pulsadores vienen de leerlos en el mismo tick y detectar el flanco (como en el tema de máquinas de estados).

```c
typedef enum { CERRADA, ABRIENDO, ABIERTA, CERRANDO, EMERGENCIA } estado_t;
static estado_t estado = CERRANDO;         // inicial de FUNCIONANDO
static int angulo = 90, t;

void barrera_tick_20ms(void) {
  if (ev_emergencia) {                                  // transición del superestado
    ev_emergencia = 0;                                  // se consume siempre, también en EMERGENCIA
    if (estado != EMERGENCIA) {
      estado = EMERGENCIA;
      angulo = 90; set_servo(angulo);                   // entry de EMERGENCIA
      return;
    }
  }
  switch (estado) {
    case CERRADA:
      if (ev_ticket) { ev_ticket = 0; estado = ABRIENDO; }
      break;
    case ABRIENDO:
      if (angulo < 90) set_servo(++angulo);             // do
      if (angulo >= 90) { t = 0; estado = ABIERTA; }    // entry de ABIERTA: t = 0
      break;
    case ABIERTA:
      if (++t >= 250 && !sensor) estado = CERRANDO;
      break;
    case CERRANDO:
      if (sensor) estado = ABRIENDO;                    // hay un coche: arriba
      else {
        set_servo(--angulo);
        if (angulo == 0) estado = CERRADA;
      }
      break;
    case EMERGENCIA:
      if (ev_rearme) { ev_rearme = 0; estado = CERRANDO; }
      break;
  }
}
```

Un TICKET pulsado mientras la barrera se mueve se queda en `ev_ticket` y la abre en cuanto llega a CERRADA. Si no se quiere, se borra `ev_ticket` al entrar en CERRADA.

</details>

## Problema 3. Depósito con histéresis

<details>
<summary>Enunciado</summary>

Un sensor de nivel da de 0 a 3,3 V (vacío a lleno) en AD0.0. Una bomba llena el depósito.

a) Diseña el control para que la bomba se encienda por debajo del 30 % y se apague por encima del 80 %. Hazlo como máquina Moore y como Mealy.
b) ¿Por qué no un solo umbral al 50 %?
c) Añade una **alarma**: si con la bomba encendida el nivel sigue por debajo del 10 % durante 10 s, se para la bomba y se enciende un LED hasta pulsar un botón.

</details>

<details>
<summary>Solución guiada</summary>

**Respuesta corta (pseudocódigo).**

```text
ADC (sensor en AD0.0):
  PCONP bit 12 = 1 · P0.23 = AD0.0
  AD0CR = SEL canal 0 | CLKDIV = 1 | PDN · START = 001 en cada tick (o con un Match)
  nivel = RESULT·100/4095

Cada 100 ms (Moore):
  según estado:
    REPOSO:   bomba = 0 · si nivel < 30 → LLENANDO
    LLENANDO: bomba = 1
              si nivel < 10: t++ · si t ≥ 100 → bomba = 0, LED = 1, ALARMA
              si no: t = 0
              si nivel > 80 → t = 0, REPOSO
    ALARMA:   si botón → LED = 0, t = 0, REPOSO
```

**Paso a paso, con el C completo:**

**a)** Dos estados: **REPOSO** y **LLENANDO**. El nivel en % sale del ADC: `nivel = resultado * 100 / 4095`.

- **Moore**: REPOSO (do: bomba = 0), LLENANDO (do: bomba = 1). Transiciones: `[nivel < 30]` REPOSO → LLENANDO y `[nivel > 80]` LLENANDO → REPOSO.
- **Mealy**: los mismos estados sin acciones dentro; `[nivel < 30] / bomba = 1` y `[nivel > 80] / bomba = 0`.

Con Moore, la salida se escribe en cada paso y siempre es coherente con el estado. Con Mealy, solo cambia al cruzar la transición.

**b)** Cerca del 50 %, el ruido del sensor y el oleaje hacen que el nivel cruce el umbral muchas veces por segundo: la bomba se enciende y apaga sin parar. Con dos umbrales, entre el 30 % y el 80 % **el estado recuerda** si se estaba llenando o no: eso es la **histéresis**.

**c)** Un estado nuevo, **ALARMA** (entry: bomba = 0, LED = 1; exit: LED = 0), y un contador en LLENANDO. Con la máquina llamada cada 100 ms:

```c
case LLENANDO:
  bomba(1);                                            // do (Moore)
  if (nivel < 10) { if (++t >= 100) { bomba(0); led(1); estado = ALARMA; } }
  else t = 0;                                          // 100 · 100 ms = 10 s seguidos
  if (nivel > 80) { t = 0; estado = REPOSO; }
  break;
case ALARMA:
  if (ev_boton) { ev_boton = 0; led(0); t = 0; estado = REPOSO; }
  break;
```

Las muestras del ADC se pueden tomar con el Timer disparando la conversión (START con un Match) y la máquina leer el último valor.

</details>

## Problema 4. Mando de infrarrojos Sony

<details>
<summary>Enunciado</summary>

Se quiere que la Mini-DK2 haga de mando a distancia con el código Sony (SIRC de 12 bits). Un LED infrarrojo, con un transistor, se conecta a MAT0.0 (P1.28). F_PCLK = 25 MHz.

- La luz va **modulada** con una portadora de **38 kHz**: «encendido» quiere decir que la portadora está activa.
- T = 600 µs. **Start**: 4T de portadora. Después, **12 bits** empezando por el de menos peso (7 de comando y 5 de dirección): un **1** es 2T de portadora y un **0** es T de portadora, cada uno seguido de **T sin portadora**.

a) ¿Cómo generas la portadora? Calcula MR0.
b) Con otro Timer, programa `tx_mando(codigo)` y la máquina que manda la trama sin bloquear.
c) En el receptor, un módulo de infrarrojos da 0 mientras recibe portadora. Mide la trama con la captura de TIMER2 en CAP2.0 (P0.4).

</details>

<details>
<summary>Solución guiada</summary>

**Respuesta corta (pseudocódigo).**

```text
Portadora (TIMER0 en MAT0.0, P1.28):
  P1.28 = MAT0.0 · MR0 = 328 · MCR = MR0R · EMR: EMC0 = 11 (conmutar)
  encender: TCR = 1 · apagar: TCR = 2 y EM0 = 0

Emisor (TIMER1, PR = 24 → 1 µs por cuenta, MR0I | MR0R, T = 600):
  tx_mando(c): bit = 0, portadora on, MR0 = 4T − 1, arrancar → START
  ISR de TIMER1 (IR = 1):
    START o MARCA: portadora off · MR0 = T − 1 → ESPACIO
    ESPACIO: si quedan bits: portadora on
                 MR0 = (bit a 1 ? 2T : T) − 1 · bit++ → MARCA
             si no: parar TIMER1 → FIN

Receptor (TIMER2 en CAP2.0, P0.4):
  PCONP bit 22 = 1 · P0.4 = CAP2.0 · PR = 24 · CCR = bajada | CAP0I · TCR = 1
  ISR de TIMER2 (IR = bit 4):
    si era bajada: guardar CR0 · CCR = subida | CAP0I
    si era subida: ancho = CR0 − guardado · CCR = bajada | CAP0I
      ESPERA_START: si ancho ≈ 2 400 µs → dato = 0, n = 0, BITS
      BITS: ≈ 1 200 µs → bit n a 1 · ≈ 600 µs → a 0 · otro → ESPERA_START
            n++ · si n == 12 → codigo_rx = dato, nuevo_codigo = 1, ESPERA_START
```

**Paso a paso, con el C completo:**

**a)** TIMER0 en **toggle** sobre MAT0.0 (EMC0 = 11) y reset en MR0: cada Match invierte el pin, así que el periodo son dos Match.

$$
MR0 = \frac{F_{PCLK}}{2\cdot 38\ \text{kHz}} - 1 = 327{,}9 \to 328
\qquad
f = \frac{25\cdot 10^6}{2\cdot 329} \approx 37\,994\ \text{Hz}
$$

Para cortar la portadora se para TIMER0 y se baja el pin (EM0 = 0), para no dejar el LED encendido.

**b)** TIMER1 con PR = 24 (F_tick = 1 MHz, así una cuenta es 1 µs y T = 600) y reset en MR0. Su ISR es la máquina: cada Match acaba un tramo y programa el siguiente.

```c
#define T 600                                    // µs (cuentas de TIMER1)
typedef enum { START, MARCA, ESPACIO, FIN } estado_tx_t;
static estado_tx_t estado_tx = FIN;
static uint16_t codigo;
static int bit;

static void portadora(int on) {
  if (on) LPC_TIM0->TCR = 1;                     // TIMER0 en marcha: 38 kHz en MAT0.0
  else { LPC_TIM0->TCR = 2; LPC_TIM0->EMR &= ~(1 << 0); }  // parado y pin a 0
}

void tx_mando(uint16_t c) {                      // 12 bits: comando y dirección
  codigo = c; bit = 0;
  estado_tx = START;
  portadora(1);
  LPC_TIM1->MR0 = 4 * T - 1;                     // start: 4T con portadora
  LPC_TIM1->TCR = 2; LPC_TIM1->TCR = 1;          // TC a 0 y arrancar
}

void TIMER1_IRQHandler(void) {
  LPC_TIM1->IR = (1 << 0);
  switch (estado_tx) {
    case START:                                  // acaba el start
    case MARCA:                                  // acaba la marca de un bit
      portadora(0);
      LPC_TIM1->MR0 = T - 1;                     // hueco de T
      estado_tx = ESPACIO;
      break;
    case ESPACIO:                                // acaba el hueco
      if (bit < 12) {
        portadora(1);
        LPC_TIM1->MR0 = (((codigo >> bit) & 1) ? 2 * T : T) - 1;
        bit++;
        estado_tx = MARCA;
      } else {
        LPC_TIM1->TCR = 0;                       // trama completa
        estado_tx = FIN;
      }
      break;
    case FIN:
      break;
  }
}
```

El MR0 nuevo se escribe justo después del Match, con el TC recién puesto a 0: hay casi T de margen antes de que haga falta.

**c)** Se mide el **ancho de cada marca** (el tiempo a 0 del receptor): 4T = 2 400 µs es el start, 2T = 1 200 µs un 1 y T = 600 µs un 0. TIMER2 (hay que encenderlo en PCONP, bit 22) con PR = 24, capturando alternativamente en bajada (empieza la marca) y en subida (acaba). Se aceptan márgenes, porque los tiempos reales varían.

```c
typedef enum { ESPERA_START, BITS } estado_rx_t;
static estado_rx_t estado_rx = ESPERA_START;
volatile uint16_t codigo_rx;                   // último código de 12 bits recibido
volatile uint8_t nuevo_codigo;                 // la ISR lo pone a 1; el programa principal lo borra al leerlo

void TIMER2_IRQHandler(void) {
  static uint32_t bajada;
  static uint16_t dato;
  static int n_bits;
  uint32_t ancho;
  LPC_TIM2->IR = (1 << 4);                       // flag de CR0
  if (LPC_TIM2->CCR & (1 << 1)) {                // estaba en bajada: empieza la marca
    bajada = LPC_TIM2->CR0;
    LPC_TIM2->CCR = (1 << 0) | (1 << 2);         // ahora, subida
    return;
  }
  ancho = LPC_TIM2->CR0 - bajada;                // µs de marca
  LPC_TIM2->CCR = (1 << 1) | (1 << 2);           // vuelta a bajada
  switch (estado_rx) {
    case ESPERA_START:
      if (ancho > 2200 && ancho < 2600) { dato = 0; n_bits = 0; estado_rx = BITS; }
      break;
    case BITS:
      if (ancho > 1000 && ancho < 1400) dato |= 1u << n_bits;      // un 1
      else if (ancho < 400 || ancho > 800) { estado_rx = ESPERA_START; break; } // ni 0 ni 1
      if (++n_bits == 12) { codigo_rx = dato; nuevo_codigo = 1; estado_rx = ESPERA_START; }
      break;
  }
}
```

Midiendo la marca (y no el periodo entre bajadas) el último bit también se mide, aunque detrás no venga otro flanco de bajada.

</details>

## Problema 5. Sonómetro con grabación y reproducción

<details>
<summary>Enunciado</summary>

Un sonómetro portátil con un LPC1768 (F_PCLK = 25 MHz en todos los periféricos) mide tres señales analógicas con el ADC y, al pulsar un botón, graba y reproduce el ruido ambiente. Las señales están en AD0.0 (micrófono), AD0.1 y AD0.3.

a) Las tres señales se leen **en ráfaga**. Calcula CLKDIV para unos 800 Hz por canal, la frecuencia real y el tiempo de conversión, y escribe el valor de `AD0CR`.
b) La grabación dura 3,2 s a 10 kHz con 8 bits, solo del micrófono (AD0.0), arrancada por MAT1.0 del Timer 1. Calcula el MR, el número de muestras y de bloques de DMA, y la memoria que ocupa. ¿Qué valor tiene `AD0CR`?
c) Escribe los ajustes del canal de DMA de la grabación.
d) La reproducción por el DAC se hace también con DMA a 10 kHz. Calcula `DACCNTVAL` y escribe los ajustes del canal.
e) ¿Cuántas interrupciones por segundo se ahorra la CPU frente a hacerlo con ISR?

</details>

<details>
<summary>Solución guiada</summary>

**Respuesta corta (pseudocódigo).**

```text
a) CLKDIV + 1 = 25·10⁶/(800·65·3) = 160,3 → CLKDIV = 159
   F_ADC = 25 MHz/160 = 156,25 kHz · f_s real = 156 250/(65·3) ≈ 801 Hz · t_conv = 65/156 250 = 416 µs
   SEL = canales 0, 1 y 3 = 0x0B · BURST = 1 · PDN = 1 · START = 000
   AD0CR = 0x0B | (159 << 8) | (1 << 16) | (1 << 21) = 0x219F0B

b) MR1 = 25·10⁶/(2·10 000) − 1 = 1249 (MAT1.0 en conmutar, reset en MR1)
   N = 10 000·3,2 = 32 000 muestras = 32 000 bytes (8 bits)
   bloques = ⌈32 000/4095⌉ = 8, de 4000 muestras (cada uno dura 0,4 s)
   AD0CR = 0x01 | (1 << 8) | (1 << 21) | (6 << 24) = 0x06200101   // t_conv = 5,2 µs ≤ 100 µs

c) origen = byte alto del resultado de AD0DR0 · destino = grabacion[]
   TransferSize = 4000 · ancho 8 bits · SI = 0 · DI = 1
   DMACCConfig = (4 << 1) | (2 << 11) | 1 = 0x1009      // petición del ADC, periférico → memoria
   8 canales encadenados con LLI; solo el último con I = 1 (y ITC)

d) DACCNTVAL = 25·10⁶/10 000 − 1 = 2499 · DACCTRL = CNT_ENA | DMA_ENA = 0x0C
   origen = grabacion[] · destino = byte alto de DACR · TransferSize = 4000 · ancho 8 bits · SI = 1 · DI = 0
   DMACCConfig = (7 << 6) | (1 << 11) | 1 = 0x9C1        // petición del DAC, memoria → periférico
   8 bloques encadenados; solo el último interrumpe

e) Con ISR serían 10 000 interrupciones por segundo; con DMA, una por bloque o una al final.
```

**Paso a paso:**

**a)** En ráfaga, cada conversión tarda 65 ciclos del reloj del ADC y se hace un canal tras otro, así que cada canal se muestrea con $f_s = F_{CLK\,ADC}/(65\cdot 3)$. Despejando, $CLKDIV + 1 = 25\cdot 10^6/(800\cdot 65\cdot 3) = 160{,}3$. CLKDIV tiene que ser entero (y $F_{CLK\,ADC} \le 13$ MHz, que se cumple de sobra): CLKDIV = 159, el divisor es 160 y salen 156,25 kHz, **801 Hz** por canal y $t_{conv} = 65/156\,250 = 416$ µs. En `AD0CR`: SEL = bits 0, 1 y 3 = `0x0B`, CLKDIV en los bits 15:8 (159 = `0x9F`), BURST (bit 16) a 1 y PDN (bit 21) a 1, con START = 000 (en ráfaga no se arranca a mano).

**b)** El Timer 1 conmuta MAT1.0 en cada Match, así que una subida de MAT1.0 (que inicia cada conversión) ocurre **cada dos Match**: $MR_1 = F_{tick}/(2f_s) - 1 = 25\cdot 10^6/20\,000 - 1 = 1249$, justo entero. $N = 32\,000$ muestras de 8 bits son 32 000 bytes. Un bloque admite 4095, y $\lceil 32\,000/4095\rceil = 8$ bloques; con 8 bloques de 4000 sale justo (0,4 s cada uno). `AD0CR`: un solo canal (SEL = `0x01`), `BURST = 0`, START = 110 (MAT1.0) en los bits 26:24 y CLKDIV = 1 para que $t_{conv} = 65/12{,}5\,\text{MHz} = 5{,}2$ µs quepa de sobra en los 100 µs: `0x06200101`. Además, `AD0INTEN` con el bit del canal 0 y **sin** habilitar la interrupción del ADC en el NVIC.

**c)** Canal de periférico a memoria: origen el byte alto del registro de datos del canal 0 del ADC (los 8 bits de más peso del resultado de 12), destino `grabacion[]`. `TransferSize = 4000`, ancho de 8 bits, `SI = 0` (el registro es fijo) y `DI = 1`. En `DMACCConfig`: `SrcPeripheral = 4` (ADC), `FlowCntrl = 010` y `E = 1`: $(4 \ll 1) \mid (2 \ll 11) \mid 1 = $ `0x1009`. Como hay 8 bloques de 4000, se encadenan 8 canales con `DMACCLLI` y solo el último lleva `I = 1`.

**d)** El DAC cuenta $DACCNTVAL + 1$ ciclos entre muestras: $25\cdot 10^6/10\,000 - 1 = 2499$. `DACCTRL` con `CNT_ENA` y `DMA_ENA`: `0x0C`. Canal memoria→periférico: origen `grabacion[]` (`SI = 1`), destino el byte alto de `DACR` (`DI = 0`), 8 bits, `DestPeripheral = 7`, `FlowCntrl = 001`: $(7 \ll 6) \mid (1 \ll 11) \mid 1 = $ `0x9C1`. Otra vez 8 bloques encadenados, con `I = 1` solo en el último.

**e)** Sin DMA, tanto al grabar como al reproducir habría 10 000 interrupciones por segundo. Con DMA, la CPU atiende como mucho una cada 0,4 s (o una sola al final de la lista).

## Problema 6. Cuatro tareas: T, D y tiempo de respuesta

<details>
<summary>Enunciado</summary>

Un sistema con un LPC1768 (CCLK = 100 MHz) tiene que hacer estas cuatro cosas:

1. Sacar una señal cuadrada de 4 kHz con un Match en conmutar.
2. Muestrear un sensor a 25 kHz con el ADC arrancado por un Timer, leyendo cada resultado con una ISR.
3. Recibir por la UART a 57 600 baudios, 8N1.
4. Un tic de SysTick cada 50 ms para temporizaciones.

a) Da T y D de cada tarea.
b) Con los tiempos de ejecución C indicados abajo y estas prioridades (de mayor a menor): muestreo, cuadrada, UART, SysTick, calcula R de cada tarea y di si el sistema es ejecutable. El `main` tiene una región crítica de 5 µs.
c) Ahora la UART tiene **el mismo nivel** que la cuadrada (la cuadrada con menor subprioridad). Recalcula R de la cuadrada y de la UART.
d) Con las prioridades del apartado b, ¿cuánto puede durar como máximo la región crítica del `main`?

| Tarea | C |
|---|---|
| Muestreo | 6 µs |
| Cuadrada | 12 µs |
| UART | 30 µs |
| SysTick | 400 µs |

</details>

<details>
<summary>Solución guiada</summary>

**Respuesta corta.**

```text
a) cuadrada: T = D = 1/(2·4000) = 125 µs      muestreo: T = D = 1/25 000 = 40 µs
   UART: T = D = 10/57 600 = 173,6 µs          SysTick: T = D = 50 ms

b) muestreo:  B = 5 · R = 6 + 5 = 11 µs ≤ 40  ✓
   cuadrada:  B = 5 · R = 12 + 5 + ⌈R/40⌉·6 → 23 µs ≤ 125  ✓
   UART:      B = 5 · R = 30 + 5 + ⌈R/40⌉·6 + ⌈R/125⌉·12 → 59 µs ≤ 173,6  ✓
   SysTick:   B = 5 · R → 741 µs ≤ 50 000  ✓      Sí es ejecutable

c) cuadrada: B = máx{5, C_UART = 30} = 30 · R = 12 + 30 + ⌈R/40⌉·6 = 54 µs ≤ 125  ✓
   UART: R = 30 + 5 + ⌈R/40⌉·6 + ⌈(R − 30)/125⌉·12 = 59 µs ≤ 173,6  ✓

d) El plazo más justo es el del muestreo: 6 + RC ≤ 40 → RC ≤ 34 µs
```

**Paso a paso:**

**a)** Con Match en conmutar, cada ISR da medio periodo: $T = D = 1/(2\cdot 4000) = 125$ µs. El muestreo a 25 kHz son 40 µs; el resultado se lee antes de la siguiente conversión. En la UART un byte 8N1 son 10 bits: $10/57\,600 = 173{,}6$ µs. SysTick, 50 ms (sin más restricciones, $D = T$).

**b)** De mayor a menor nivel: muestreo, cuadrada, UART y SysTick, todos de niveles distintos. Los bloqueos vienen solo de la región crítica del `main` (5 µs): el resto de tareas sí se pueden interrumpir.

- *Muestreo*: nadie la interfiere. $R = 6 + 5 = 11$ µs ≤ 40.
- *Cuadrada*: $R_0 = 12 + 5 = 17$. Con 17, $\lceil 17/40\rceil\cdot 6 = 6$ → 23. Con 23, otra vez 6 → 23. **23 µs** ≤ 125.
- *UART*: $R_0 = 30 + 5 = 35$. Con 35: $\lceil 35/40\rceil\cdot 6 + \lceil 35/125\rceil\cdot 12 = 18$ → 53. Con 53: $12 + 12 = 24$ → 59. Con 59: $12 + 12$ → 59. **59 µs** ≤ 173,6.
- *SysTick*: $R_0 = 405$. Con 405: $11\cdot 6 + 4\cdot 12 + 3\cdot 30 = 204$ → 609. Con 609: $16\cdot 6 + 5\cdot 12 + 4\cdot 30 = 276$ → 681. Con 681: $18\cdot 6 + 6\cdot 12 + 4\cdot 30 = 300$ → 705. Con 705: $18\cdot 6 + 6\cdot 12 + 5\cdot 30 = 330$ → 735. Con 735: $19\cdot 6 + 6\cdot 12 + 5\cdot 30 = 336$ → 741. Con 741: 336 → **741 µs** ≤ 50 000.

Todas cumplen $R \le D$: **es ejecutable**. El SysTick tarda 741 µs en acabar en el peor caso, y aun así es mucho menos que sus 50 ms.

**c)** Ahora la UART y la cuadrada son del mismo nivel y no se interrumpen. *Cuadrada*: si la UART acaba de empezar, la cuadrada espera a que termine: $B = \max\{5,\ C_{UART} = 30\} = 30$. $R_0 = 12 + 30 = 42$; $\lceil 42/40\rceil\cdot 6 = 12$ → 54; $\lceil 54/40\rceil = 2$ → 54. $R = 54$ µs ≤ 125 ✓. *UART*: la cuadrada **no la interrumpe**, así que solo se cuela antes de que empiece: se usa $R - C$: $R = 30 + 5 + \lceil R/40\rceil\cdot 6 + \lceil (R - 30)/125\rceil\cdot 12$. Con $R_0 = 35$: $6 + \lceil 5/125\rceil\cdot 12 = 18$ → 53; con 53: $12 + 12 = 24$ → 59; con 59: $12 + 12$ → 59. $R = 59$ µs ≤ 173,6 ✓. Sigue siendo ejecutable.

**d)** La que tiene menos margen es la de muestreo (plazo de 40 µs): $R = C + RC \le D$ → $RC \le 40 - 6 = 34$ µs. Con 34 µs, la cuadrada tendría $R = 12 + 34 + 2\cdot 6 = 58$ ≤ 125 (el muestreo la interrumpe dos veces) y la UART seguiría por debajo de 173,6, así que manda el muestreo.

</details>
